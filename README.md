# windower

A tiny, fast macOS CLI to list and focus windows. Native Swift, single binary,
no dependencies. Built because macOS is bad at switching between windows.

## What it does

- Lists open windows (`ID | App | Window title`).
- Focuses a specific window — not just the app — by window number or by text.
- Optional interactive picker.

## Build

```bash
swift build -c release   # binary at .build/release/windower
```

## Make a local binary

```bash
./install.sh             # builds and copies the binary to ./windower (repo root)
```

This lets you run it right from the repo (`./windower list`). A Homebrew formula
would run `swift build -c release` and install `.build/release/windower` into its
own prefix, so this script doesn't install to a fixed system path.

## Homebrew

The Homebrew formula lives in this repo (`Formula/windower.rb`), so install via a
URL-tap (Homebrew 6 requires trusting the tap):

```bash
brew tap 750/windower https://github.com/750/windower.git
brew trust 750/windower                       # Homebrew 6: trust the tap
brew install windower
```

The formula installs a **prebuilt binary** from a GitHub Release (built on CI), so
`brew install` doesn't compile anything. Homebrew 6 nonetheless requires a recent
Xcode/CLT to run the install step unless a Homebrew **bottle** is published, so on
a machine with an old toolchain you'll need to update the CLT (or we can publish
bottles via the tap CI).

On Homebrew 6 this tap is registered as `750/homebrew-windower` (it normalizes the
name), but the source is the same `750/windower` repo.

### Prebuilt binary without Homebrew

If you just want the binary and don't need `brew`:

```bash
curl -L https://github.com/750/windower/releases/download/v0.2.0/windower-0.2.0.tar.gz | tar -xz
./windower list
# or put it on your PATH
sudo mv windower /usr/local/bin/windower
```

## Usage

```bash
windower                 # print the manual (help)
windower list            # list on-screen windows
windower list --all      # also include minimized / other-space windows (slower, noisier)
windower list --json     # machine-readable output
windower focus 3683      # focus on-screen window by number (from `list`)
windower focus Safari    # focus on-screen window by fuzzy text match on app/title
windower focus --all Safari  # also search minimized / other-space windows (opt-in, slower)
windower pick            # interactive picker (on-screen windows)
windower --help
```

`focus` matches text against `"<app> <title>"`, prefers a prefix match, then the
earliest substring match. Passing a bare number selects by window ID. By default
`focus` searches **on-screen** windows only (fast + clean); pass `--all` to also
search minimized and other-Space windows.

## Running from Karabiner / launchd / scripts

Karabiner's `shell_command` (and most launchd jobs) run via `/bin/sh` with a
*minimal* PATH that usually does **not** include `~/.local/bin`, so a bare
`windower` there fails with `command not found`. Always use the absolute path:

```
/Users/jarvis-hmac/.local/bin/windower focus scratchpad
```

If your Karabiner config is generated by goku, edit the source `.edn` and re-run
`goku` (don't hand-edit `karabiner.json` — it gets regenerated).

## Permissions

macOS sandboxes window APIs, so you need to grant permission once in
**System Settings → Privacy & Security**:

- **Accessibility** — required to focus a *specific* window (and to read window
  titles when Screen Recording is not granted). Without it, `focus` can only
  activate the app, not raise the exact window.
- **Screen Recording** — optional. When granted, `list` reads titles straight
  from the window server, making listing instant (the fast path). When not
  granted, titles come from Accessibility instead.

The binary checks trust and prints a short hint when a permission is missing.

## How it stays fast

- `list` uses `CGWindowListCopyWindowInfo` (sub-millisecond) and, when Screen
  Recording is available, reads titles from the window server directly — no
  per-app Accessibility pass over the whole list. Steady-state `list` ≈ 50 ms.
- Accessibility is only touched lazily for the **one** window you focus, so the
  cost isn't paid across every window.
- Windows are enumerated by the window server and filtered to layer-0 application
  windows (menus, status bar, dock, and desktop are excluded).

## Limitations

- Raising a window that's on another Mission Control space may not switch spaces
  (macOS restricts this); `list --all` shows such windows but focusing them can
  be best-effort.
- A single non-public symbol (`_AXUIElementGetWindow`) is used to map a
  `CGWindowID` to its Accessibility element. It's stable and widely used, but it
  is technically private API and could change with a future macOS release.
